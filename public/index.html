This PC — the whole app, one double-click
The site, the downloader, the song model and the voice, in one environment — one virtualenv, the voice included, not a second one — plus whatever the pool needs to reach it. It fetches its own Python 3.11 and git, installs the CUDA build of torch, all four services (site 5001, downloads 8080, song 8090, voice 8095) and the ~10 GB of model weights, then starts everything and registers it to come back at every logon. No administrator prompt and nothing to install first. About 20 GB of disk, an NVIDIA driver 560 or newer for the card, and 20–60 minutes depending on the connection; the window keeps printing what it is doing, and closing it stops the install. It asks once for the join key, which whoever runs this site gives out: that key is what adds a machine to the pool every visitor's song is rendered on. It is not printed on this page on purpose — it is a write credential for the pool, so anyone holding it could point other people's songs at a machine of their own. Without it the install still finishes and the AI runs on this PC for this PC alone.

Open a free GPU notebook — the notebook in your own Google account, on a free T4: nothing is installed on this PC, you press Run all, and the card puts itself in this pool — no address to paste into Connect my model, because the site reads the pool. It does that once SONG_JOIN_KEY is stored as a Colab secret (key icon on the left): one paste there, and every run joins by itself. Without that secret the card stays private and its last cell prints one address for Connect my model. The card leaves when the session ends.

Both routes join the same pool, and the join key is the only door: this notebook is public, so anyone can run it, but a card without SONG_JOIN_KEY in their own Colab secrets never joins this pool — their address is theirs alone. Nobody can put a GPU in this pool without the key.

Using the pool is open to everyone, on any computer: the page asks this site for a GPU and sends the song there, so a visitor connects to whichever card is in the pool — the one that joined last first, and the other if that one stops answering — with nothing to paste. The key decides who may add a card, not who may use one.

Where the model itself runs — never on this site, always on a card:
• This PC, Windows with an NVIDIA card: Start the AI installs it and runs it here on 127.0.0.1:8090. Private to this computer until it joins the pool, which needs the join key.
• A Linux box or server with an NVIDIA card: the same notebook cell runs there, or install song_service/requirements.txt and run app.py --role song; a tunnel is what makes it reachable.
• Kaggle: Start Kaggle uses the pool owner's Kaggle account, so it starts a card of theirs — not one under your name.
• Colab: any Google account can open the notebook and press Run all on a free T4; without SONG_JOIN_KEY the card stays private and prints an address, with it the card joins this pool.
• A Mac, or a PC without an NVIDIA card: the service starts on the CPU and does work, but one song takes many minutes — not recommended.
• Phone or tablet: nothing to install; use this page, which is what the pool is for.

Start Kaggle — this card is shared instead: it runs here for everybody and joins this pool, so it needs a Kaggle account. Kaggle gives you 30 hours a week of GPU time: when that runs out the card stops, the tunnel closes and this pool loses that machine — start another one from here.

Expect it to take a while before any song can use it: a fresh kernel copies the repository, unpacks the packages and pulls roughly 10 GB of model weights before the model can load, so it appears in the pool several minutes after the press, not immediately.
